## なぜ作ったか

AI に文書を渡すには、まずテキストにしなければなりません。ところが **HWP はそれが
できません。** docx や pdf を読むツールはいくらでもありますが、韓国語文書にはほとんど
なく、**韓国の公文書はそのほとんどが HWP** です。

そして、文字だけ取り出しても半分です。**検索の質は構造が残っているかで決まります** —
表が地の文に潰れると検索が外れ、見出しがなければ文書を切る境界が取れません。

そこで既定の出力を **Markdown** にしました。表は `|` の表として、シートは `##` の
見出しとして出ます。Markdown はそのままチャンク化する流儀がすでに定着しているので、
既存のパイプラインにそのまま入ります。

```
116 ページの公文書 1 件 → Markdown 193,000 文字・表 91 個
```

91 個の表がすべて残ります。プレーンテキストで取り出すと、そのすべてが地の文になります。

## 使い方

展開したフォルダの中で（macOS・Linux）

```bash
./kayatext 議事録.hwp                  # 議事録.md を出力
./kayatext *.hwp *.xlsx -o out/        # 複数をひとつのフォルダへ
./kayatext 文書.hwp --txt              # プレーンテキスト（構造は捨てる）
./kayatext 文書.hwp -                  # 標準出力へ（パイプ用）
./kayatext --version
./kayatext --licenses                  # オープンソース表示
./kayatext --terms                     # 使用条件（ライセンス窓口を含む）
```

Windows PowerShell では `.\` を付け、拡張子も必要です。

```powershell
.\kayatext.exe 議事録.hwp
.\kayatext.exe *.hwp *.xlsx -o out\
.\kayatext.exe 文書.hwp --txt
.\kayatext.exe --version
```

`PATH` に入れれば先頭の `./` は要りません —
[どこからでも呼ぶには](#どこからでも呼ぶには)を参照してください。

**1 つ失敗しても止まりません。** 失敗の一覧をまとめて最後に報告し、1 つでも失敗すれば
終了コード 1 を返します — スクリプトが判定できなければ意味がないからです。

### メッセージの言語

ヘルプとエラーは**ロケールに従います**。韓国語と英語の 2 つだけです。

```bash
LANG=ko_KR.UTF-8 kayatext 文書.hwp     # 韓国語
LANG=C           kayatext 文書.hwp     # 英語
KAYATEXT_LANG=en kayatext 文書.hwp     # ロケールに関わらず英語
```

`LANG` が `ko` で始まれば韓国語、それ以外は英語です。Windows では `LANG` がないのが
普通なので、**システムの表示言語**を見ます。

> 7 言語にしていない理由があります。ターミナルの共通語は英語であり、エラー文を
> 7 通りにすると、Issue に貼っていただいた 1 行をこちらが読めなくなります。

### 受け付ける形式

`.hwp` `.hwpx` `.hml` `.xlsx` `.xlsm` `.docx` `.rtf` `.pdf`

RTF は段落までしか読みません — 元に表があっても地の文になります。これは私たちが
捨てたのではなくパーサーが渡してくれないもので、結果にそう書き添えます。

PDF は座標から構造を組み直します — **罫線のある表と見出しは残り、罫線のない表は
地の文になります。** 原本（ハングル・Excel・Word）があれば、そちらの経路が表を
すべて残します。

`.pptx` `.doc`（旧形式）はまだです。

## ダウンロード

| | |
|---|---|
| **macOS (Apple Silicon)** | ✅ [`kayatext-macos-arm64.tar.gz`](../../releases/latest) |
| **Windows (x64)** | ✅ [`kayatext-windows-x64.zip`](../../releases/latest) |
| **Linux (x64)** | ✅ [`kayatext-linux-x64.tar.gz`](../../releases/latest) |
| macOS (Intel) | 後回し |
| Linux (ARM64) | 後回し |

Linux 版は**静的リンク（musl）**なのでディストリビューションを選びません。Ubuntu・
Debian・Alpine・CentOS のいずれでも、展開すればそのまま動きます。コンテナに入れる
ときも別途ライブラリを入れる必要がありません。

展開すると 4 つ入っています。

```
kayatext        実行ファイル
rhwp            HWP 変換器 — これがないと .hwp が扱えません
LICENSE.txt
THIRD-PARTY-NOTICES.md
```

**インストールは不要です。** フォルダごと動かして構いません。`rhwp` が隣にありさえ
すれば動きます。

**macOS・Linux**

```bash
# macOS
tar xzf kayatext-macos-arm64.tar.gz && cd kayatext-macos-arm64

# Linux
tar xzf kayatext-linux-x64.tar.gz && cd kayatext-linux-x64

./kayatext --version
```

**Windows** — PowerShell は現在のフォルダを探さないので `.\` が要ります。
`cmd.exe` なら `kayatext` だけで動きます。

```powershell
cd kayatext-windows-x64
.\kayatext.exe --version
```

### どこからでも呼ぶには

`PATH` に置けば先頭の `./` なしで使えます。**2 つを同じフォルダに**置いてください —
`rhwp` が隣にないと `.hwp` が扱えません。

```bash
sudo cp kayatext rhwp /usr/local/bin/          # macOS・Linux
```

```powershell
# Windows — フォルダごと移して、そのフォルダを PATH に入れるほうが簡単です
move kayatext-windows-x64 C:\tools\kayatext
setx PATH "%PATH%;C:\tools\kayatext"
```

> **署名がないので OS が一度止めます。** 個人プロジェクトのため、開発者証明書をまだ
> 付けていません。**壊れたファイルではありません。**
>
> - **macOS** — システム設定 → プライバシーとセキュリティ →「このまま開く」
> - **Windows** — SmartScreen の青い画面で「詳細情報」→「実行」

## 通らない文書を教えてください

試験用に作ったファイルでは捕まらないバグがあります。**実際の文書にしかないもの**が
あるからです — 11 列の結合、図形が混ざった表、古い版のワープロで作られた書式。

### いちばん助かるもの

**公開されている政府・公共機関の文書**です。公告、書式、報道資料 — ファイルを送って
いただく必要はなく、**ダウンロードできるアドレスだけ**で十分です。

### 会社の文書なら — 上げないでください

業務文書には氏名や連絡先が入っており、**作成者はファイル情報にも残ります。** 公開の
場に上げると取り消せず、上げた方が困ることになりかねません。

代わりに**症状だけ**書いてください。「表のある 3 ページの公文書で、2 ページ目から
罫線が消える」程度で、似たファイルを作って再現します。どうしてもファイルが必要なら
非公開でやり取りし、匿名化の方法をご案内します。

### お礼

いただいたものが実際にバグを捕まえたり、回帰テストに入ったりしたら —

- 回帰テストの一覧にお名前を載せます（ご希望があれば）
- **企業ライセンス証書を無償でお渡しします。** 会社でもどこでも元々無料なので、使うのに
  必要なものではありません。導入審査や監査で**書類を出さなければならない方**にだけ
  価値があります

証書のために無理をしてファイルを送らないでください。
**アドレス 1 つがファイル 10 個に勝ります。**
