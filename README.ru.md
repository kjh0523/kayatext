## Зачем это нужно

Прежде чем отдать документ ИИ, из него нужно сделать текст. **С HWP это не
получается.** Для docx и pdf извлекателей полно, для корейских документов почти нет —
а **корейские государственные документы почти все в HWP**.

Вытащить одни лишь символы — это только половина дела. **Качество поиска зависит от
того, уцелела ли структура**: таблица, размазанная в сплошной текст, находится плохо, а
без заголовков нет границы, по которой документ можно разрезать.

Поэтому вывод по умолчанию — **Markdown**. Таблицы выходят таблицами `|`, листы —
заголовками `##`. Markdown и без того режут на фрагменты как есть, так что он ложится
прямо в существующие конвейеры.

```
один государственный документ на 116 страниц → 193 000 знаков Markdown · 91 таблица
```

Все 91 таблица уцелевают. При извлечении в простой текст каждая из них превращается в
сплошной текст.

## Как пользоваться

Из распакованной папки (macOS · Linux)

```bash
./kayatext протокол.hwp                # получится протокол.md
./kayatext *.hwp *.xlsx -o out/        # много файлов в одну папку
./kayatext документ.hwp --txt          # простой текст (структура отбрасывается)
./kayatext документ.hwp -              # в стандартный вывод (для конвейеров)
./kayatext --version
./kayatext --licenses                  # уведомления об открытом ПО
./kayatext --terms                     # условия использования (с контактом)
```

В Windows PowerShell нужен `.\` и расширение.

```powershell
.\kayatext.exe протокол.hwp
.\kayatext.exe *.hwp *.xlsx -o out\
.\kayatext.exe документ.hwp --txt
.\kayatext.exe --version
```

Если положить в `PATH`, ведущий `./` не нужен — см.
[Вызов откуда угодно](#вызов-откуда-угодно).

**Один сбойный файл не останавливает работу.** Неудачи собираются и сообщаются в конце,
и если хоть одна была, код возврата равен 1 — скрипт должен уметь это распознать.

### Язык сообщений

Справка и ошибки **следуют вашей локали**. Языка два: корейский и английский.

```bash
LANG=ko_KR.UTF-8 kayatext документ.hwp     # корейский
LANG=C           kayatext документ.hwp     # английский
KAYATEXT_LANG=en kayatext документ.hwp     # английский независимо от локали
```

Если `LANG` начинается с `ko` — корейский, иначе английский. В Windows, где `LANG`
обычно не задан, берётся язык интерфейса системы.

> Семи языков здесь нет, и на то есть причина. Общий язык терминала — английский, а с
> семью версиями каждой ошибки я не смог бы прочитать строку, которую вы вставите в
> issue.

### Принимаемые форматы

`.hwp` `.hwpx` `.hml` `.xlsx` `.xlsm` `.docx` `.rtf` `.pdf`

RTF читается только до уровня абзацев — если в оригинале есть таблицы, они выйдут
сплошным текстом. Это не мы выбросили: синтаксический анализатор их не отдаёт, и в
результате об этом сказано.

Для PDF структура восстанавливается по координатам — **таблицы с линиями и
заголовки сохраняются, таблицы без линий выходят сплошным текстом.** Если есть
оригинал (Hangul, Excel, Word), этот путь сохраняет все таблицы.

`.pptx` и `.doc` (старый формат) пока не поддерживаются.

| macOS (Intel) | позже |

Сборка для Linux **слинкована статически (musl)**, поэтому дистрибутив не важен —
Ubuntu, Debian, Alpine, CentOS работают прямо из архива. Для контейнера тоже не нужны
дополнительные библиотеки.

В архиве четыре вещи.

```
kayatext        исполняемый файл
rhwp            конвертер HWP — без него .hwp не работает
LICENSE.txt
THIRD-PARTY-NOTICES.md
```

**Установка не нужна.** Переносите папку целиком куда угодно; важно лишь, чтобы `rhwp`
лежал рядом.

**macOS · Linux**

```bash
# macOS
tar xzf kayatext-macos-arm64.tar.gz && cd kayatext-macos-arm64

# Linux
tar xzf kayatext-linux-x64.tar.gz && cd kayatext-linux-x64

./kayatext --version
```

**Windows** — PowerShell не ищет в текущей папке, отсюда `.\`. В `cmd.exe` достаточно
`kayatext`.

```powershell
cd kayatext-windows-x64
.\kayatext.exe --version
```

### Вызов откуда угодно

В `PATH` можно обойтись без `./`. **Держите оба файла вместе** — без `rhwp` рядом `.hwp`
работать не будет.

```bash
sudo cp kayatext rhwp /usr/local/bin/          # macOS · Linux
```

```powershell
# Windows — проще перенести папку целиком и добавить её в PATH
move kayatext-windows-x64 C:\tools\kayatext
setx PATH "%PATH%;C:\tools\kayatext"
```

> **Подписи нет, поэтому система один раз вас остановит.** Это личный проект, сертификат
> разработчика к нему пока не приложен. **Файл не повреждён.**
>
> - **macOS** — Системные настройки → Конфиденциальность и безопасность → «Всё равно
>   открыть»
> - **Windows** — в синем окне SmartScreen «Подробнее» → «Выполнить в любом случае»

**Это не открытое ПО.** Полный текст — в `LICENSE.txt` внутри архива.

**Бесплатно для всех** — и для частных лиц, и для компаний, и для госучреждений, школ,
некоммерческих организаций, для коммерческого и некоммерческого использования.

**Никаких ограничений возможностей.** Платной редакции не существует; распространяется
одна-единственная сборка. В ней нет кода, который считает использование или запирает
функции.

## Расскажите о документах, которые не поддаются

Некоторые ошибки не ловятся файлами, сделанными для тестов. **Они бывают только в
настоящих документах** — объединение на 11 столбцов, таблица с врезанными фигурами,
форма, сделанная в старой версии текстового процессора.

### Что помогает больше всего

**Опубликованные документы государственных и общественных учреждений.** Объявления,
формы, пресс-релизы — файл присылать не нужно, **достаточно адреса, по которому его
можно скачать**.

### Если это рабочий документ — не выкладывайте его

В служебных документах есть имена и контакты, а **автор остаётся ещё и в свойствах
файла**. Выложенное в открытый доступ не вернуть, и это может обернуться неприятностями
для вас.

**Опишите вместо этого только симптом.** Что-нибудь вроде «служебное письмо на
3 страницы с таблицами, со второй страницы пропадают линейки» — мне этого хватит, чтобы
сделать похожий файл и воспроизвести. Если файл действительно нужен, обменяемся им
непублично, и я подскажу, как его обезличить.

  бумаги** при закупочной проверке или аудите

Не присылайте файлы через силу ради свидетельства.
**Один адрес лучше десяти файлов.**
